# Files and custody

## Import and working state

An import resolves a media object already admitted in the room, validates its
custody and writes bounded bytes into the scope's inbox. The VM never contacts
Nora's object store. The source remains attributable to the room and media
row, not a filename the model guessed.

Working files live on real POSIX storage in the scoped workspace. Projects,
lockfiles, generated data and long-job output can persist across turns while
Nora's conversation remains stateless. Observed file state is read fresh when
needed rather than remembered in doctrine.

Exports move bytes out through the runtime's bounded read and are checked on
Nora's side for size, actual content type and digest. Extension or VM-provided
MIME alone is not authority. A missing file is unavailable, never an empty
artifact.

## Export destinations

A chat export returns the file as an attachment to the admitted target. A
link export publishes bytes through Nora's authenticated artifact custody and
returns the portal location. A kept export stores private bytes and a manifest
for later continuation, including media references a document may use.

Every destination records the room, scope, source path, digest, publication
identity and provenance. Revising with the same publication identity can keep
the same link while replacing bytes through the ordinary revision path. The VM
never receives the publication credential or decides its own URL.

Active web content is not a passive file export. HTML and other active forms
follow the document/publication security boundary rather than being uploaded
as an arbitrary download. Documents are JSON specs published by the document
tool, not pages generated by this sandbox.

## Backup and restore

Host backup preserves scoped workspaces before destructive lifecycle actions
and on its operational schedule. It is not an off-host guarantee, and it never
publishes private browser profiles or credentials to the artifact catalog.

The scheduled archive excludes every scope's `browser/` directory — a Chromium
profile is a credential store — while the archive taken before a destructive
lifecycle action is complete, browser profiles included, and stays
host-private. It accounts for every regular file, including user-authored
files in environments; unsafe links, sockets and FIFOs may be omitted only
with exact receipts. Source inventory reconciles against actual entries and
allowed omissions, so a missing regular file fails rather than creating a
plausible-looking backup.

Restore preserves scope ownership and content digests, recreates interpreter
and runtime links through their owning tools and refuses unaccounted paths.
A failed backup or restore leaves the prior archive and working state intact.

A destructive recreate requires a verified backup or an explicit operator
decision. Recovery never remaps one scope into another or trusts a VM-supplied
manifest over the source inventory.
