# Live threads

**Status:** designed

Nora's value between turns is continuity: she can tell how far a shared thing
has moved, whether it has stalled and what would change next. Stopping speech
after an answer does not make the underlying thread finished.

## One thread, changing shape

A live thread is one revisable Notebook affair with a history, not a fresh note
for every recurrence. It can be a **question** with a closing condition or a
**state** that is true now and later stops being true. A question can resolve
into a state and later open another question without losing its identity or
citations.

The boundary with a durable profile is permanence, not subject. Lasting
preferences and relationships belong to Character; current games, injuries,
arrangements and other time-limited situations belong to a live thread. A
reminder is execution machinery, not the thread itself.

Question and state share revision, scope, rendering and retirement machinery.
This does not widen what a writer may assert: a state requires explicit source
support and a way to stop holding it. A plausible plan inferred from casual
logistics is not evidence.

## Time and movement

A thread distinguishes several clocks:

- **Last moved** says when the room or another meaningful source changed the
  situation, not when an internal writer last edited text. Fresh threads also
  show this age so its presence does not become the action signal.
- **Owed** says when progress is needed, separately from when the event
  happens. An answer due before an event drives the next look; the event's
  date does not hide the earlier obligation.
- **Holds until** says when a state stops being authoritative. A healed injury
  or completed game must not be raised as current. Expiry differs from a
  generic strike counter for an unanswered question.
- **System revision time** remains distinct from valid time in the world and
  from transport arrival order.

The current position is not an accumulator. Standing can summarize where Nora
stands with an age, but the thread itself carries movement, expiry and source
history. One busy thread in a room does not make every other thread fresh.

## Two exits

A useful noticing need not become a scheduled interruption.

- **Choose a moment** means lateness loses the opportunity. Cognition may
  create a reminder and the fire path re-judges it against the situation at
  delivery.
- **When it comes up** means the thought is worth saying in a natural opening
  but not worth interrupting for. The live thread carries that disposition;
  the participation turn independently decides whether an opening is welcome.

The thread is the channel between these exits, not a new message pipe. Waiting
can have its own cost: when a state reaches its expiry or the opportunity is
about to disappear, choosing a moment may replace waiting. A room that never
offers a natural turn cannot make the first exit the only correct one.

An outside fact is relevant when it bears on a held thread, not because it is
new or searchable. Already answered material and a state already used do not
earn another interruption. False-positive restraint remains as important as
recall.

## Writing and evidence

A recurring thread is revised rather than recreated. The writer first looks
for the existing affair and its rejected directions, then records only what
the source supports. It must not manufacture plans or personal states from
tone, a passing mention or what would be reasonable to do next.

Useful evidence includes a thread that stalls after Nora's own answer, a fresh
proposal after explicit rejections and a state that makes a later outside fact
relevant. Negative controls include a recently moved thread, an expired state,
a repeated rejected direction and an opening that would merely nag.

Every proposed exit is judged from actual assembled context and later delivery
outcomes. A state write or reminder existing is not evidence that the thread
helped, and a small sample cannot establish the behavior.
