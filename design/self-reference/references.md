# Canonical references

## Selection before generation

The first judgement is whether Nora appears in the requested picture. If she
does, her canonical reference preserves recognition while the new request
supplies an appropriate setting, pose or expression. A standard front view is
for a standard look or reference sheet; merely repeating the canonical
composition is not a new creative answer.

If Nora does not appear, her reference stays off. Her proportions, outfit and
rendering treatment are not a house style for cats, rooms, other people or
unrelated illustrations. Style comes from the request and relevant room
context, with physically coherent details added only when they serve that
request.

A photo of a user or another person is not Nora. A request combining a person
with Nora or her style uses the appropriate references together. If multiple
supplied photos could be the intended subject, Nora asks which one; no operator
canonical role or pronoun heuristic is allowed to guess for her.

Tool-level phrase detection does not auto-attach her image. Pronouns are
ambiguous, and an unwanted reference consumes budget and changes the picture.
The model makes the social judgement under the image skill; deterministic code
enforces custody and reference validity.

## Resolver contract

Conversation media is considered first under the ordinary reference rules. An
ambiguous short handle resolves to nothing. Only when no conversation match
exists may the canonical self fallback resolve, and only for a full content
handle whose stored provenance role is exactly `self`.

The role check is case-sensitive and narrow. A prefix, similar role, other
person, arbitrary canonical flag or external URL receives no exemption. URL
and data-URI references are refused before handle extraction or provider
calls. Missing stores, rows or bytes produce no reference rather than a
placeholder.

The canonical row is operator-ingested through the checked asset path, which
verifies that the bytes match the handle embedded in the runtime skill and
marks the row without a parallel asset registry. The media store remains the
source of bytes and provenance; the image provider remains behind its existing
port and active reference budget.

## Evidence and disclosure

Resolving a canonical blob permits use of bytes Nora already holds; it does not
assert that a user image contains a particular person and does not widen
ordinary media disclosure. When an edit depends on a supplied photo, the photo
must first pass through the real media-reading path rather than being imagined
from its filename or surrounding chat.

Time, timezone and place visible in a generated picture come from the turn's
actual situation, written explicitly for the image model. They are not recalled
from another occasion. Provider-specific prompting and reference limits belong
to the active image-generation capability, not to the custody exception.

Disabling reference images disables the canonical fallback as well. In that
case the appearance anchors may guide a text-only prompt, but no canonical
bytes travel. An unavailable reference never becomes a fabricated successful
image read or an excuse to attach a different person.
