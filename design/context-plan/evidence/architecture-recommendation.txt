# Context selection: source-grounded recommendation

The source agrees with the broad hypothesis, with a consequential coupling:
`TranscriptInjection.assemble` in `nora/engagement/context.py` gathers transcript,
cards, Standing, notes, presence, Culture, character, computer, documents and
subagents concurrently. `EngagementPipeline._run_turn` builds a `Room` and tool
surface before calling `nora.agent.prefill.build_prefill`. That builder declares
and assembles named `ContextBlock`s. Runtime availability and model exposure are
different properties.

1. **Contract and evaluation point.** A future runtime `ContextPlan` belongs with
   context data in `nora/domain/blocks.py`, independently of `EngageDecision`.
   Evaluate it after full assembly and before constructing `Room` and the prefill.
   The current experiment's contract lives only in `nora/subject/context_filter.py`;
   no runtime planner or config switch is introduced.
2. **Phase 1.** Yes: retain full `assemble()` retrieval and filter exposure at the
   existing block-assembly seam. It tests exposure, not retrieval savings.
3. **Selector input.** Normalized current message, tagger name/card, clock, Culture
   and Standing with their provenance/time, a recent transcript with speakers and
   ages, and available candidate descriptions/previews. The experiment uses the
   last eight transcript rows and 600-character optional previews. This is not a
   proven sufficient substrate for all turns; uncertain selection includes context.
4. **Mandatory versus selectable.** Keep the authored head, current/quoted message,
   tool admission/catalogue, room identity/membership, presence, self and peer cards,
   notes/decisions, Culture/character, Standing/working set and transcript intact
   initially. Test only peer_history, documents, computer and subagents as optional.
5. **Culture and Standing.** Both should reach Nora as well as the selector in the
   first experiment. They describe the room and Nora's current conversational
   position. Delegating their interpretation entirely to a selector would make it
   a second reasoning stage.
6. **Transcript depth.** Fixed at the full assembled transcript initially, including
   any quote-expanded window. The source binds numbered transcript positions to
   tool references. Reducing depth needs one coherent remap across prompt, quote,
   Room/tool surfaces and notes; a prompt-only tail is insufficient.
7. **Failure.** Preserve full context. Invalid names, changed depth, malformed
   responses and transport failures are recorded as selector errors, not successful
   plans. A successful reply under fallback does not pass the router experiment.
8. **Caching and latency.** The experiment leaves the static main-model head/tool
   schemas unchanged. Changing volatile context can still change cache hits; use
   measured cached/fresh usage, not character savings as a price estimate. Phase 1
   adds a serial selector request after parallel reads. Phase 2's base-read → API →
   selected-read chain may be slower than the existing gather despite fewer reads.
9. **Evidence.** Per-draw selected, available and actually withheld blocks; selector
   errors and timing; exposure sizes; model/provider/cache identity and selector
   usage; existing Nora token/cache/tool grades; replay settlement time. One draw
   is a smoke check. Tool grades do not establish reply quality. The known judge
   timeout defect remains outside this change.
10. **Model choice.** Deterministic rules are the zero-call baseline. DeepSeek V4.1
    Flash is the cloud candidate the operator authorized, with encouraging small
    synthetic measurements. Tev1 4B also passed optional-block smoke choices but was
    slower on the current iGPU. Neither result establishes end-to-end benefit.
    JEV, specialized/multilingual Laya and Strands plus pre-ranker are not justified
    without comparable measurements. Keep the main model as the only reply author.

## A source coupling the experiment must preserve

`Room.tagger_card_injected` specifically means **peer_history is exposed**.
`about` in `nora/agent/tools.py` uses it to skip a duplicate memory read and return
`already_present`. The experiment therefore records the actual Room temporarily
and updates this flag from the selected rendered blocks before tool execution.
Otherwise hiding history would also remove Nora's ability to retrieve it. A runtime
planner should supply that exposure fact directly to Room's constructor.

The recommendation holds unless anchored downstream replay shows a material net
benefit with no required-context losses. Transcript selection and selective
retrieval remain separate, later experiments.
