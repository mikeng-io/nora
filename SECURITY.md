# Security

## Reporting a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/mikeng-io/nora/security/advisories/new)
when it is available for this repository. Include the affected revision, impact
and a minimal synthetic reproduction. Do not send credentials, personal messages,
account identifiers or location histories.

If private reporting is unavailable, email the maintainer at
[iam@mikeng.io](mailto:iam@mikeng.io) to request a private reporting channel.
This route also accepts Code of Conduct reports. Keep sensitive details out of
the initial request. Keep exploit details out of public issues and pull requests
until a fix and disclosure have been coordinated.

## Scope and maintenance

Nora is experimental. Security fixes target the current default branch; older
releases do not have a separate security maintenance commitment. Reports and fixes
are handled on a best-effort basis, without a guaranteed response time.

Each operator manages their installation's credentials, platform registrations,
network access and backups. Use synthetic fixtures for development and keep
production configuration and data outside version control.
