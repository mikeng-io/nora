# site — Nora's public site

The page at `/` (繁體中文) and `/en/` (English): what Nora is, shown rather than
listed. Static Astro, no client framework. Small vanilla scripts do the work
in the browser: the chat demo (`site/src/scripts/chat.ts`), the lighting and
language choices (`site/src/scripts/prefs.ts`), the character-sheet viewer
(inline in `site/src/components/Form.astro`), her notebook under the memory
tiers (`site/src/scripts/memory.ts`), the loop diagram's signal
(`site/src/scripts/loop.ts`), sound (`site/src/scripts/sound.ts`), and Nora
herself (`site/src/scripts/nora/`). Without script the page still reads in
full: the chat renders as a finished transcript, and every place she can be
shows her static render.

## Nora, live

She lives in the page rather than being pictured on it (DESIGN.md §6,
Presence). One WebGL2 canvas is her body and one brain is her behaviour
(`site/src/scripts/nora/`): she breathes, blinks, looks where you point,
listens to her music when left alone, dozes off when left longer, and gives
you a look if you keep poking her. She is in one place at a time: the hero's
studio, the edge of the chat window, her stool in the memory section, the
manners column, the photo plate, the portal panel (and the 404). Each place is
marked `data-nora-slot` and holds her static render; she hops to whichever you
are reading, and the one she left stands empty. The header shows what she is
doing, the way a chat app shows the line under a name.

The page talks to her through events, so each part works without the others:
the chat demo emits `nora:room` (she looks up at what you asked and thinks),
her notebook (`memory.ts`) rewrites its fast tiers from the same events and
emits `nora:writing`, and "Hear her" emits her voice's loudness as
`nora:voice`. `wire.ts` is where those meet her.

What she is drawn from (cut-outs of her renders with the eyes and mouth
painted out, the empty studios, where everything is) is `src/assets/rig/`,
generated by `site/scripts/make_rig.py`; its README has the command. Her voice
clips and how they were made: `src/assets/voice/README.md`.

`/` is the zh-Hant page, as the portal's default is. An English-first browser
that has not picked a language is sent to `/en/` (the portal's next-intl did
the same); picking one in the switch is remembered.

It replaces the portal's old landing route (`app/src/app/[locale]/page.tsx`).
The portal is still the only place anyone signs in; every "Sign in" here links
to the portal's `/<locale>/login`.

## Design

`DESIGN.md` binds it: its tokens are `src/styles/tokens.css` one for one, and
its two themes are the page's two lightings, Studio and Late night. The hero
portrait and the character plate switch with the lighting, the studio portrait
by day and its late-night twin by night. What the page adds to DESIGN.md is a
display register (the large type a public page needs), recorded in DESIGN.md
§4.

Motion follows DESIGN.md §6: the interface moves only to confirm (messages
enter in 240ms, changing the lighting is a 240ms cross-fade), and Nora herself
is the live state its Presence register describes. Reduced motion, a data
saver or no WebGL2 leave her as her static renders; sound is off until the
header's earphones are put in.

## Run it

```bash
cd site
npm ci
npm run dev       # http://localhost:4321
npm run build     # astro check, then the static build in dist/
```

The build fails if a page uses a Chinese character that the committed Noto
Sans HK subset does not have (`site/scripts/cjk-coverage.mjs`). After changing
Chinese copy, run `npm run fonts` (it downloads the 11 MB source font once
into `.cache/`) and commit `src/fonts/noto-sans-hk-subset.*`.

Icons and link-preview images are generated, not drawn:
`uv run --no-project --with pillow --with fonttools --with brotli python site/scripts/make_images.py`
from the repo root. The art is in `src/assets/art/` (provenance in its
`README.md`); Nora's canonical images come straight from the repo's `assets/`.
Her rig is generated from that art by `site/scripts/make_rig.py`
(`src/assets/rig/README.md`); rerun it after changing a render.

## Copy

`src/i18n/en.ts` and `src/i18n/zh-hant.ts`, checked against one shape
(`src/i18n/types.ts`) by `astro check`, so a key in one language and not the
other fails the build. Every capability the page claims is from `README.md`'s
opening and its tool list; change the page when those change.

## Going live

The container serves the build on `127.0.0.1:3401` (`docker-compose.yml`,
service `site`, profile `site`). It owns only these paths:

```text
^/$  ^/en/?$  ^/_astro/  ^/_site/  ^/favicon\.ico$  ^/robots\.txt$
^/sitemap\.xml$  ^/llms\.txt$  ^/wiki(?:/.*)?$
```

Nothing there collides with the portal (`/_next/`, `/api/`, `/zh-Hant/…`,
`/en/…`, `/manifest.webmanifest`, `/sw.js`, `/offline.html`, `/icons/`,
`/vendor/`, `/screenshots/`; app/README.md), so the site can share the portal's
hostname: the tunnel sends those paths to `:3401` and everything else to the
portal. Owning `/robots.txt` means answering for the portal too:
`src/pages/robots.txt.ts` keeps "never index" for `/artifacts/`, `/api/` and the
signed-in locale pages (Drop's `/drop/` and `/i/` rules left with Drop, ADR 0023). In order:

1. `docker compose --profile site build site && docker compose --profile site up -d site`
2. The tunnel's ingress: the paths above to `http://localhost:3401`, before the
   portal's catch-all.
3. The portal's `/[locale]` page stops being a landing page: it redirects to
   its own `/[locale]/login`, which forwards a signed-in person to `/status`,
   and the old landing copy is deleted. Not to the site: without the tunnel
   (local dev) `/` reaches the portal, which sends it back to `/zh-Hant`, a
   loop.

Live since 2026-09-26: the tunnel rule is in `~/workspace/cloudflared/terraform/tunnel.tf`
on norty, just before the portal's catch-all. `/sitemap.xml` and `/llms.txt`
joined it on 2026-09-27; a path added to the list above is unreachable until
it is added there too.

If the portal ever gets a hostname of its own, build with
`PUBLIC_PORTAL_ORIGIN=https://<portal host>` so the sign-in links follow it,
and `SITE_ORIGIN` for the canonical URLs.

## Implementation wiki

`docs-site/` renders the reviewed Markdown in `openwiki/` with Astro Starlight.
The site Dockerfile builds it separately and serves its output at `/wiki/` in
this same Caddy container. The build makes no inference calls. See
[the wiki workflow](../docs-site/README.md) for generation, PR checks and the
provider configuration. A tunnel ingress match for `/wiki` and `/wiki/…` must
reach port 3401 before the portal's catch-all; Caddy alone cannot change it.

The PR build uploads the combined homepage and wiki as a static artifact. It
has no live deployment credentials and does not change the tunnel.
