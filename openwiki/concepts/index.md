# Files

- [Context assembly](context-assembly.md) - How one turn's prompt is built — doctrine selected by audience and scope, the ordered prefill block table whose per-block key says what the content varies by (and therefore how many prefixes exist), typed blocks that declare what they are, and the architecture tests that keep every model prompt assembled.
- [Contextual learning: response episodes, Standing, Character/Culture and Lessons](contextual-learning.md) - How Nora's stored context changes from the outcomes of her own sends — the Rollup response episode as the shared unit, the post-turn Standing fold, the Character and Culture revision chains, and the Lessons chain with its citation, echo and doctrine checks, plus where each one re-enters the prompt.
- [Memory and the Record](memory-and-record.md) - How Nora's memory is layered — the authoritative Record, the derived SQL memory index that answers retrieval (projection, embeddings, graph and vector search), and Honcho's role as interpretation rather than record — plus the two independent rollback axes (retrieval surface and Persona rendering), how the two surfaces stay exclusive, and what the migration still leaves wired to Honcho.
- [Persona: typed account lines, reasoning modes and supersession](persona-and-provenance.md) - How the Persona tier keeps one account per entity as append-only typed lines — the parts, kinds and reasoning modes with their evidence floors, the citation and egress rules a line must satisfy, the plan_write judge and the store transaction that refuse an unlawful line, precedence and supersession when two lines conflict, disputes and hypothesis verdicts, and how an account is rendered back into a prompt.
- [Policy, admission and disclosure boundaries](policy-and-disclosure.md) - How Nora decides who may talk to her, where, and about what — the deny-by-default policy.toml grant model and its startup refusals, identity resolution to people, the engage and relevance-gate verdicts, the per-room MCP tool grant enforced at tool assembly on the tag path, the separate disclosure gates (room grant, live roster and circle subset, location trust, degraded-roster refusal, lineage at assembly, reply screening), and the egress, tool-argument and trace screens that gate what she may say.
- [Sessionless continuity: what a speaking turn actually is](sessionless-continuity.md) - Why Nora's speaking path builds a fresh Strands agent from assembled context on every turn with no SDK session manager, which state the prefill rehydrates and which it never could, what is reconstructed per turn versus stored, and where background cognition legitimately keeps bounded sessions of its own.
- [The tool surface: scopes, shelves, budgets and the guard](tool-surface.md) - How a native tool becomes callable and how each turn is constrained — the one registry every loop draws from, the declared resident hot set and the per-turn deferred shelf, the five scope dimensions, the single budget table the guard enforces, default-deny for absent tools, undeclared arguments and over-cap results, plus the naming and contract-metadata rules a tool must meet.
