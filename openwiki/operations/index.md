# Files

- [Configuration: capability flags, validation and the config CLI](configuration.md) - How a Nora deployment is configured and what a flag actually switches: the validated, frozen config schema, the three-file split as lifetimes and review surfaces, secrets that are only ever environment-variable names, the nora config mutation CLI and its validate-before-apply discipline, and a capability-flag table mapping each optional subsystem to the code that is built when it is on, absent when it is off, and the behaviour a reader sees — including the one flag that also buys a tag-turn-only model-facing tool surface.
- [Deployment: the Compose topology, the image, and the deploy transaction](deployment.md) - How Nora's root Compose project is built: the service inventory, inbound publishes separated from outbound connectivity, the networks that are actually internal, the version-stamped image and its fail-closed reader, the conditional choice between checkout and Komodo deployment modes, the validate-then-recreate transaction, and why rollback is bounded by schema and config compatibility rather than image retagging.
- [Observability: metrics, traces, logs, errors and health](observability.md) - How to read Nora back: the division of labour between Prometheus metrics, Langfuse and Jaeger traces, stdout logs, Sentry errors and the /health endpoint; the plumbing sampler this repository owns and the two collector pipelines it does not; how [obs.tracing] exports, why export failures are silent, the declaration and priming rules that keep metric series readable, and what a green health check cannot prove.
- [Diagnosing a failure: symptom, owner and evidence](troubleshooting.md) - A cross-system triage map: which speaking routes an installation may have, the common symptom classes, the page that owns each flow, the counters, attributes and log lines that discriminate the cause, and which operator commands read without writing.
