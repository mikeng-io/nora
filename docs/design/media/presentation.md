# Presentation

## Shared media is for her, not an inventory

A person who shares media already knows what it shows. The transcript and the
read tool give Nora what she needs to notice, not a list to translate back.
A request to describe gets what she noticed; a practical question gets the one
fact that answers it, such as the error, the price or the place.

## A result says what it is

Each part of a media result carries its role, so one successful but partial
read cannot stand for the whole:

- a **reading** is a model's reading, not a fact to vouch for;
- a **caption** is the poster's words;
- a **cover** is a still, not the clip;
- **unread** and **not read here** name what remains available, and do not
  prompt a blanket retry of every failed item.

A caption in a transcript is an excerpt that visibly stops, so it is not
mistaken for the whole post; the source and the post read hold it complete.

## A linked post is read as the item

A linked post or reel points to the item itself, so its cover is not offered
as a second, easier read. A story's cover can remain, because a story link
reads the current story rather than necessarily the shared frame. When a link
is invalid or missing, the cover is the only faithful content and stays. A
generic web or media fetch cannot divert a social page link around the social
reader and its rules ([social](../social/README.md)).

## Discovery and reading are separate calls

Discovery returns candidates and references; reading returns what an item shows.
Their costs and meanings differ, so a profile or a search reads no media, while
a post or a story uses the same reader with its own bounded slots and per-item
outcomes. A further look that would answer a different question than the first
is the model's explicit choice.
