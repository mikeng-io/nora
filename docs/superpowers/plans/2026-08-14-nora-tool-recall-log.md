# Nora Tool-Recall Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A gathered fact (a place's rating, a route's duration, a web
search) can be reused later in the SAME conversation instead of forcing a
re-query, closing the gap the operator hit directly: "for the past 10 or 20
messages... if I suddenly ask Nora to put that in a report... it probably
has to search all over again."

**Architecture:** `NativeTool` gains a declared `cacheable: bool = False`
field, mirroring how `budget`/`terminal` already work — true today for
exactly five tools (`place_info`, `route`, `web_search`, `weather`,
`transit`). A new `ToolCallLog` hook provider (`nora.agent.guards`) writes
one row per successful cacheable call to a new `tool_call_log` table,
scoped to the conversation. A new on-demand tool, `recall_lookups`, reads
the last N rows within a 7-day window, newest first. R-45's existing nudge
(DEC-101) is extended, status-aware, to also fire when `recall_lookups`
found something and `make_artifact` still got empty `context`.

**Tech Stack:** Python 3.12/3.13, SQLAlchemy Core + Alembic (Postgres),
Strands Agents SDK, pytest.

**Spec:** `docs/superpowers/specs/2026-08-14-nora-tool-recall-log-design.md`
— read it first; it carries the reasoning (why an allowlist, why on-demand
not auto-injected, why not vector similarity) this plan does not repeat.
An independent subagent review corrected several claims in the spec's
first draft; the spec's own "Revision note" and inline corrections record
what changed and why — this plan implements the CORRECTED spec.

## Global Constraints

- `cacheable` defaults `False` — a future tool ships un-cacheable until
  someone makes the call explicitly, at its own `NativeTool` entry, the
  same direction every other declared field on that type already defaults
  safe.
- Exactly five tools are cacheable in this plan: `place_info`, `route`,
  `web_search`, `weather`, `transit`. No other tool's `cacheable` changes.
- `recall_lookups` is on-demand (a native tool the model calls), never
  auto-injected into every prompt.
- Scope is ALWAYS one `conversation_id`. No cross-conversation read, ever.
- Window is 7 days (`created_at > now() - interval '7 days'`), recency
  ordering only — no topic filtering, no embeddings, no vector search
  (spec §1's own YAGNI argument).
- A call that was vetoed, or whose own `status` was anything other than
  `"ok"`, writes NOTHING to the log — not `refused`, not `unavailable`,
  not `nothing_found`.
- `AfterToolCallEvent.result` carries Strands' OWN `{"status":
  "success"/"error", "content": [{"text": <json>}]}` wrapper, not the
  tool's own status — every task that reads a tool's real status goes
  through the shared `_unwrap_tool_status` helper (Task 5), never
  `event.result["status"]` directly.
- Migration `0010_tool_call_log`, following `0009_compute_job_hashes` —
  hand-written (not autogenerated) because the new index is a `... DESC`
  shape autogenerate is blind to, the same reason `idx_messages_conv_ts`
  is hand-written.
- New rule numbers for this plan: **R-46** ("only a cacheable tool's
  successful call is ever logged") and **DEC-102** (this feature's own
  decision-index row). R-45/DEC-101's existing row is AMENDED, not
  replaced, in Task 8.
- Every gate must pass at the end: `uv run pytest -q`,
  `uv run ruff check nora/ evals/ tests/`,
  `uv run mypy nora/domain nora/config.py nora/app nora/infra nora/presence`,
  `uv run lint-imports`, the schema-parity suite, a release fragment.

Create `nora/domain/tool_call_log.py`:

```python
"""The tool-recall log port (tool-recall-log spec §2, §7). One row per
successful call to a `cacheable=True` tool (`nora.agent.tools.NativeTool`),
scoped to one conversation — read back only by `recall_lookups`, itself
scoped to the same conversation. Never cross-conversation, ever.

Every datetime crossing this port is UTC-aware, the same rule
`nora.domain.compute`'s module docstring states for `ComputeJobStore` — a
separate local rule/helper here, not imported from that module, since the
two ports are independent even though the rule is identical.
"""

from __future__ import annotations

from dataclasses import dataclass, replace
from datetime import UTC, datetime
from typing import Any, Protocol, runtime_checkable
from uuid import UUID


class NaiveToolCallLogDatetimeError(ValueError):
    """A datetime reached `ToolCallLogStore` without a timezone."""


def ensure_utc_log(value: datetime, *, field: str) -> datetime:
    if value.tzinfo is None or value.utcoffset() is None:
        raise NaiveToolCallLogDatetimeError(
            f"{field} must be timezone-aware; got naive {value!r}."
        )
    return value.astimezone(UTC)


@dataclass(frozen=True, slots=True)
class ToolCallLogEntry:
    """One cacheable tool's successful call, logged for later reuse.

    `tag_id` is the transcript anchor this call happened under — given a
    row, you can find which turn produced it, bounded by however long that
    turn's own row survives `messages`'s own pruning (spec §6).
    `tool_input`/`tool_result` are the tool's own arguments and return
    value; `recall_lookups` (Task 7) hands them back to the model exactly
    as stored, never re-summarised.
    """

    id: UUID
    conversation_id: str
    conversation_type: str
    tag_id: str
    tool_name: str
    tool_input: dict[str, Any]
    tool_result: dict[str, Any]
    created_at: datetime


def normalise_tool_call_log_entry(entry: ToolCallLogEntry) -> ToolCallLogEntry:
    return replace(entry, created_at=ensure_utc_log(entry.created_at, field="created_at"))


@runtime_checkable
class ToolCallLogStore(Protocol):
    async def append(self, entry: ToolCallLogEntry) -> None:
        """Insert-only. Never called for a vetoed call or a call whose own
        `status` was not `"ok"` (R-46) — that discipline lives in the
        WRITER (`nora.agent.guards.ToolCallLog`, Task 5), not here; this
        port stores exactly what it's given."""
        ...

    async def recent(
        self, *, conversation_id: str, since: datetime, limit: int,
    ) -> list[ToolCallLogEntry]:
        """The last `limit` entries for `conversation_id` with `created_at
        >= since`, newest first. `since` is the caller's job to compute
        (`recall_lookups`, Task 7, passes `now() - 7 days`) — this port
        takes an absolute timestamp, never a relative window, so a fake
        clock in a test needs no special-casing here."""
        ...
```

Create `nora/infra/sql/tool_call_log.py`:

```python
"""`ToolCallLogStore` over SQLAlchemy Core. Shaped like
`nora.infra.sql.compute_jobs`, minus the state machine — a log entry is
insert-only and never updated.
"""

from __future__ import annotations

from datetime import datetime
from typing import Any

import sqlalchemy as sa
from sqlalchemy.engine import Row
from sqlalchemy.ext.asyncio import AsyncEngine

from nora.domain.tool_call_log import ToolCallLogEntry, normalise_tool_call_log_entry
from nora.infra.sql.schema import TOOL_CALL_LOG


def _row_to_entry(r: Row[Any]) -> ToolCallLogEntry:
    return normalise_tool_call_log_entry(
        ToolCallLogEntry(
            id=r.id, conversation_id=r.conversation_id,
            conversation_type=r.conversation_type, tag_id=r.tag_id,
            tool_name=r.tool_name, tool_input=r.tool_input, tool_result=r.tool_result,
            created_at=r.created_at,
        )
    )


class SqlToolCallLogStore:
    """Satisfies `nora.domain.tool_call_log.ToolCallLogStore`."""

    def __init__(self, engine: AsyncEngine) -> None:
        self._engine = engine

    async def append(self, entry: ToolCallLogEntry) -> None:
        row = normalise_tool_call_log_entry(entry)
        stmt = sa.insert(TOOL_CALL_LOG).values(
            id=row.id, conversation_id=row.conversation_id,
            conversation_type=row.conversation_type, tag_id=row.tag_id,
            tool_name=row.tool_name, tool_input=row.tool_input,
            tool_result=row.tool_result, created_at=row.created_at,
        )
        async with self._engine.begin() as conn:
            await conn.execute(stmt)

    async def recent(
        self, *, conversation_id: str, since: datetime, limit: int,
    ) -> list[ToolCallLogEntry]:
        stmt = (
            sa.select(TOOL_CALL_LOG)
            .where(
                TOOL_CALL_LOG.c.conversation_id == conversation_id,
                TOOL_CALL_LOG.c.created_at >= since,
            )
            .order_by(TOOL_CALL_LOG.c.created_at.desc())
            .limit(limit)
        )
        async with self._engine.connect() as conn:
            rows = (await conn.execute(stmt)).all()
        return [_row_to_entry(r) for r in rows]
```

```python
def _unwrap_tool_status(result: Any) -> str | None:
    """The tool's OWN status (`ok`/`refused`/`unavailable`/...), unwrapped
    from Strands' own success/error envelope.

    `AfterToolCallEvent.result` is a `strands.types.tools.ToolResult` —
    `{"status": "success"/"error", "content": [...], "toolUseId": ...}` —
    which is STRANDS' verdict on whether the call raised, not the tool's
    own semantic answer. Every native tool in this codebase returns a plain
    dict with no `content` key, so `DecoratedFunctionTool._wrap_tool_result`
    always takes its ELSE branch: `content` becomes `[{"text":
    json.dumps(the_tools_own_dict)}]`. Reaching the real status means
    parsing that text back out — this is the one place in the codebase that
    does, shared by `ToolCallLog` (this module) and `ReplyGuard`'s R-45
    check (`evaluate`, below) so the unwrap logic exists exactly once.

    Returns `None` for a result shaped in a way this cannot parse (a tool
    that returns a bare value with no `status` key at all — `now`,
    `send_reply`, `load_transcript` all do this today) — callers treat
    `None` as "not `ok`", never as "assume ok"."""
    try:
        content = result["content"]
        payload = json.loads(content[0]["text"])
    except (KeyError, IndexError, TypeError, json.JSONDecodeError):
        return None
    return payload.get("status") if isinstance(payload, dict) else None


class ToolCallLog(HookProvider):
    """Write path for the tool-recall log (R-46, tool-recall-log spec §3).
    Constructed fresh per tag, like `ReplyGuard`.

    A DIFFERENT responsibility from `ReplyGuard` (veto/budget logic) — this
    is persistence, so it is its own small collaborator and its own
    `HookProvider`, not a method bolted onto `ReplyGuard`. `store=None` is
    the honest INERT default (offline/eval compositions, or any deployment
    that has not wired one) — a missing store means every write is a no-op,
    never a raised error and never a fallback that pretends to remember
    something it didn't (R-5's shape, applied to a write path rather than a
    read).
    """

    def __init__(
        self, *, conversation_id: str, conversation_type: str, tag_id: str,
        cacheable: frozenset[str], store: Any, metrics: Metrics,
        clock: Callable[[], datetime] = datetime.now,
    ) -> None:
        self._conversation_id = conversation_id
        self._conversation_type = conversation_type
        self._tag_id = tag_id
        self._cacheable = cacheable
        self._store = store
        self._metrics = metrics
        self._clock = clock

    async def _after_tool_async(self, event: Any) -> None:
        try:
            if getattr(event, "cancel_message", None) is not None:
                return
            name = (getattr(event, "tool_use", None) or {}).get("name", "")
            if name not in self._cacheable:
                return
            if _unwrap_tool_status(event.result) != "ok":
                return
            if self._store is None:
                return
            tool_input = (getattr(event, "tool_use", None) or {}).get("input") or {}
            # `content[0]["text"]` is `json.dumps(the tool's own dict)` —
            # see `_unwrap_tool_status`'s own docstring — so this second
            # `json.loads` is the tool's REAL return value, not Strands'
            # wrapper. Guarded the same way `_unwrap_tool_status` is;
            # unreachable here in practice since that call already
            # succeeded above, but never assume a second parse of the same
            # string cannot fail for a reason the first one didn't hit.
            try:
                tool_result = json.loads(event.result["content"][0]["text"])
            except (KeyError, IndexError, TypeError, json.JSONDecodeError):
                return
            from uuid import uuid4

            from nora.domain.tool_call_log import ToolCallLogEntry

            entry = ToolCallLogEntry(
                id=uuid4(), conversation_id=self._conversation_id,
                conversation_type=self._conversation_type, tag_id=self._tag_id,
                tool_name=name, tool_input=tool_input, tool_result=tool_result,
                created_at=self._clock(),
            )
            await self._store.append(entry)
        except Exception:
            # Decoration on a turn that has already completed correctly
            # without it (spec §3) — never let a log write cost the reply
            # that already went out.
            log.exception("ToolCallLog write failed; ignoring")

    def register_hooks(self, registry: HookRegistry, **kwargs: Any) -> None:
        registry.add_callback(AfterToolCallEvent, self._after_tool_async)
```

        """Pull back facts you (or an earlier turn) already looked up in
        THIS conversation, within the last 7 days — a place's rating, a
        route's duration, a web search's results. Call this before
        re-running place_info/route/web_search/weather/transit for

            return {"status": "unavailable"}

                "tool_result": r.tool_result,
                "age_seconds": (now - r.created_at).total_seconds(),
